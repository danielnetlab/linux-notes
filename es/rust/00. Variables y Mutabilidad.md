## 00.01 Cómo se crean las variables
Una **variable** es un nombre asociado a un valor. Se crea con `let`:
``` rust
let x = 5; // x se llama así, vale 5, Rust deduce su tipo "i32"
```
---
## 00.02 Mutabilidad en variables
Al crear una variable, **por defecto es inmutable**, lo que implica que no puede modificarse después de la declaración. Esto evita:
- Bugs raros
- Código difícil de leer
- Problemas de seguridad
``` rust
let password = 5;
password = 6; // error al compilar porque es inmutable
```
---
## 00.03 Mutabilidad: permitir cambios
Para poder cambiar el valor de las variables, debe ser declarado con `mut`, la variable sigue siendo la misma pero con diferente valor:
``` rust
let mut x = 5;
x = 6; // compila bien
```
Una vez declarada la variable, se puede modificar su valor, pero no su tipo de dato. El tipo queda definido en el momento de la declaración y no puede cambiarse después.
``` rust
let mut x = 5; // x es i32
x = 10; // compila bien
x = 3.13; // ERROR porque cambia el tipo, no puedes pasar a float
```
---
## 00.04 Operadores de asignación compuesta

| Operador | Expresiones | Significado           |
| -------- | ----------- | --------------------- |
| `+=`     | `x + 1`     | suma y reasigna       |
| `-=`     | `x - 1`     | resta y reasigna      |
| `*=`     | `x * 1`     | multiplica y reasigna |
| `/=`     | `x / 1`     | divide y reasigna     |
Sirven para **modificar una variable aplicando una operación**.
``` rust
let mut x = 5;
x = x + 1; // forma larga
x += 1; // forma corta (misma idea, más cómodo)
```

## 00.05 Ámbito (scope) de las variables
Es la zona del código donde una variable:
- existe
- es accesible
- es válida
En Rust, los ámbitos se definen con **bloques** `{}`.
``` rust
fn main() { // ámbito
    let x = 5;
    println!("{x}");
}
```
- `x` existe **solo dentro de `main`**
- fuera de `main`, `x` no existe
``` rust
fn main() { // ámbito
    let x = 5;
    
    { // ámbito
	    let y = 10;
	    println!("{x} {y}");
    }
    
    println!("{x}");
    println!("{y}"); // error: ya no existe aquí
}
```
---
## 00.06 Cuándo una variable deja de existir
Una variable:
- **nace** cuando se declara
- **muere** cuando termina su ámbito
Rust controla estrictamente para evitar:
- accesos a memoria inválida
- referencias a datos que ya no existen
``` rust
fn main() {
	let x = 5;
	
	{
		let x = 10;
		println!("{x}"); // 10
	}
	
	println!("{x}"); // 5
}
```
Aquí se ve:
- hay **dos variables distintas**
- cada una vive en su ámbito
- no se pisan realmente
---
## 00.07 Shadowing (sombreado)
Ocurre cuando declaras una variable con el mismo nombre que otra ya existente, haciendo que la nueva variable oculte a la anterior, dejando inaccesible la variable previa desde ese punto del código.
``` rust
let x = 5;
let x = x.to_string(); // ahora x es String
```
### Diferencia real: `mut` vs shadowing
- Con `mut`: cambias el valor de la misma variable.
- Con shadowing: creas una variable nueva y "tapas" la anterior. Puedes **cambiar el tipo** de la variable.
---
## 00.08 Tiempo de vida básico (lifetime conceptual)
Aún no veremos lifetimes avanzados (`'a`), pero la idea es esencial:
> **Una variable vive mientras su ámbito esté activo.**

Cuando el ámbito termina:
- la variable se destruye
- su memoria se libera
- ya no se puede usar
Esto evita errores como:
- usar datos que ya no existen
- referencias colgantes
> En Rust, **no existe el recolector de basura (GC)**.

## 00.09 Turbofish
El **turbofish** (`::<>`) **especifica explícitamente los parámetros de tipo genéricos**, cuando el compilador de Rust no puede inferirlos automáticamente.
``` rust
let x = "5";
let y = x.parse::<i32>();
```
---
## 00.10 Convertir texto a número
Un número entre comillas es un **&str** (una referencia a texto). Rust no permite operaciones entre tipos incompatibles debido al sistema de tipos en el cual veremos más adelante. `.parse()` **no devuelve el número directamente**, devuelve un `Result`. Convertir el texto al tipo objetivo:
``` rust
let user_age = "123";
let user_age = user_age.parse::<i32>();
```
Devuelve el resultado o un error, cosa que ya veremos más adelante.
``` rust
let user_age = "manzana";
let user_age = user_age.parse::<i32>(); // error
```
---
## 00.11 Que devuelve `.parse()` realmente
`.parse()` devuelve un tipo llamado:
- `Result<T, E>`
Que significa:
- **Ok(T)** -> salió bien, aquí el valor
- **Err(E)** -> salió mal, aquí tienes el error
Si en Rust no se trata el error, no se compila.
``` rust
let n: Result<i32, _> = "54".parse::<i32>();
```
- Si la conversión va bien: `Ok(54)`
- Si va mal: `Err(...)`
---
## 00.12 Controlar a `.parse()`
Como `.parse()` devuelve un `Result`, no se sabrá si devuelve un `Ok(T)` o `Err(E)`. Aquí viene `.unwrap()`, que si sale `Ok(valor)` te saca el `valor`, pero si sale `Err(error)`, **peta el programa** (panic) y muestra el mensaje de panic.
``` rust
let x = "54".parse::<i32>().unwrap(); // x es i32
```
**Cuándo usar** `unwrap()`
- En ejemplos y aprendizaje
- En prototipos rápidos
- Cuando estás 100% seguro de que no fallará
- En código serio, se suele usar `match` o `expect` o `?` (eso vendrá más adelante).
- Si puede fallar por entrada externa, no uses `unwrap`.
``` rust
let x = "hola".parse::<i32>().unwrap(); // panic
```

## 00.13 Constantes
Las constantes son inmutables de forma **permanente** y hay que declararle el tipo obligatoriamente. Se evalúan en **tiempo de compilación**. Por convención, el identificador de la constante se escribe en MAYÚSCULAS.
``` rust
const SEGUNDOS_EN_UNA_HORA: u32 = 60 * 60;
```
---
## 00.14 `let` vs `const` vs `static`
- `let` -> variable en tiempo de ejecución
- `const` -> valor conocido en compilación
- `static` -> valor global con dirección fija en memoria, lo veremos más adelante.
---
## 00.15 Convenciones de nombres
- Variables -> `snake_case`
- Constantes -> `MAYUSCULAS_CON_GUIONES`
- Evitar `x`, `y` salvo ejemplos
- Nombres que expliquen intención

## 00.16 Errores comunes
- olvidar `mut`
- intentar cambiar el tipo con `mut`
- confundir shadowing con reasignación
- usar `unwrap` sin pensar
- intentar usar una variable fuera de su ámbito
- asumir que `=` compara valores
